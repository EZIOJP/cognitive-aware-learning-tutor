```markdown
## `MT1-T02` — LCM & HCF

**What it is:** HCF (GCD) is the greatest shared divisor; LCM is the least shared multiple. For positive integers \(a,b\): \(\mathrm{HCF}(a,b)\times\mathrm{LCM}(a,b)=a\times b\).

**How to compute:** Prime-factorise both numbers. HCF takes the **lowest** power of each shared prime; LCM takes the **highest** power of every prime that appears.

**Classic patterns:**
- Largest number dividing \(a\) and \(b\) → HCF
- Least time/distance when events repeat → LCM
- Largest tape that cuts lengths without leftover → HCF of the lengths

**Takeaway:** Word problems are almost always “shared factor” (HCF) vs “shared schedule/multiple” (LCM).
```

Heading + trimmed body (full body is longer on disk; digester returns full section):

```markdown
## `L5-T05` — Unique values: `unique()`, `nunique()`, `value_counts()`

**What it is:** Three levels of uniqueness questions: list values (`unique`), count (`nunique`), frequency table (`value_counts`). Pick the one that matches the business question.

**Key rule:** unique = what values exist; nunique = how many; value_counts = how often each.

**Syntax:** `series.unique()`, `series.nunique()`, `series.value_counts()`.

**When to use it:** When exploring categories, counts, or cleaning repeated rows.

> **`value_counts()` always sorts descending by count** — chaining `.head(n)` gives “top N most common.”

| Method | Answers |
|---|---|
| `.count()` | How many non-null rows total? |
| `.nunique()` | How many distinct categories? |
| `.value_counts()` | How many rows fall into each category? |
```

**Read card id:** `L05_pandas_operations_notes.md::L5-T05`

**How the stitch works:**

1. Topic-level `note_topic_ids: ["MT1-T02"]` links the whole pack to the note section.  
2. Item-level `tags` are free tags (`mathgenerator`, `gen-9`) — also appear in the Study Loop tag index.  
3. `content_bank.list_topics(note_topic_id="MT1-T02")` / `build_quiz_items(note_topic_id=...)` returns these items.  
4. `handler.start_session(domain="math", config={"note_topic_id": "MT1-T02", "count": 5})` loads bank items then **fills shortfall from live math_generators** with the same MT tag.  
5. After answers, `upsert_review_card` schedules FSRS; Due tab resurfaces them.

Selecting tag `MT1-T02` in Study Loop therefore yields:

```text
read card  ← note section
questions  ← gen-lcm.json (+ other packs / generators with MT1-T02)
due        ← ReviewCards created from those practices
```

## 6. Schema notes (`content_schemas.py`)

Fields that matter for stitching and Study Loop:

| Field | Where | Why it matters |
|-------|--------|----------------|
| `schema_version` | file | Must be `1` |
| `kind` | file | Today: `"math"` \| `"coding"`; planned: + `"mcq"` \| `"coding_mcq"` |
| `topic.topic_id` | topic | Stable slug, e.g. `math.aptitude.gen-lcm` |
| `topic.note_topic_ids` | topic | **Primary stitch** to `L*` / `MT*` note sections |
| `topic.path` / `stage` / `track` | topic | Curriculum UI / filters |
| `questions[].id` | item | Stable id for ReviewCard `item_key` / catalog lookup |
| `questions[].problem` / `answer` | math | Prompt + key; empty → open |
| `questions[].answer_format` | math | `number` \| `expression` \| `text` \| `open` |
| `questions[].tags` | item | Free-tag stitch + filters |
| `questions[].test_cases` | coding | Harness inputs for `code_runner` |
| `questions[].entry_point` | coding | Function call mode vs script/`expected_stdout` |

`CONTENT_KINDS` today = `("math", "coding")`. Study Loop plan extends to MCQ packs under `data/questions/mcq/`.

## 7. Vocab stitch sketch (planned)

GRE bank: `public/data/words.json` (loaded via vocab services).

| Mechanism | Rule |
|-----------|------|
| Group tag | Every word with `group_number: N` links to tag `vocab.group.N` |
| Free tags | Word `tags[]` appear in Study Loop tag list |
| Attach | `add_tag` / PATCH appends a free tag or note topic id onto selected words |
| Practice | `POST /api/quiz/start` `{ "domain": "vocab", "config": { "group_number": N } }` or `word_ids` |
| Read gate | Vocab-only tags have **no** read card → `read_completed` auto-true |

Example conceptual tags after Task 6:

```text
vocab.group.2     kind=vocab_group  vocab_count=30  has_read_card=false
emotion           kind=free         vocab_count=…   (from word tags)
MT1-T02           kind=note_topic   question_count=… has_read_card=true
```

## 8. End-to-end story for tag `MT1-T02`

```text
1. User opens Daily Learn → Loop → picks MT1-T02
2. GET /study-loop/read-cards?tag=MT1-T02
   → body matches note section “LCM & HCF”
3. Optional PATCH → write-back into MT1_aptitude_interview_notes.md
4. mark-read → read_completed=true
5. start-practice → handler.start_session(domain=math, note_topic_id=MT1-T02)
   → items from gen-lcm.json (+ generator fill)
6. Each answer → upsert_review_card (FSRS)
7. Due tab shows those cards later — same SRS as everything else
```

No second flashcard table. Notes remain the only source of truth for read text.
